# Shafa Watcher

Стежить за новими лістингами на [shafa.ua](https://shafa.ua) за базою брендів і надсилає в Telegram фото, назву, бренд, розмір, стан, ціну (зі знижкою) і посилання.

- Джерело даних: прихований GraphQL API Shafa (той самий, що використовує сайт). Деталі — у [FINDINGS.md](FINDINGS.md).
- Запуск: GitHub Actions кожні 10 хв (приватний репозиторій, безкоштовна квота); запуски роблять три незалежні тригери ([нижче](#самозапуск-три-шари)).
- Усе безкоштовно: GitHub Actions + Google Apps Script + Cloudflare Workers Free + Telegram Bot API.

> ✅ **Працює з 9.11.2026 (кожні 10 хв, три шари самозапуску):** 580 брендів зі списку «Бренди для моніторингу Shafa / OLX», 6 пакетів частоти, 196 текстових пошуків. Звіт опитування брендів: [docs/brand_survey.md](docs/brand_survey.md). Повний стан проєкту: [BIBLE.md](BIBLE.md).

## Як це працює

1. `brands.yaml` → правила (бренд, пошук усередині бренду або пошук без бренду). Правила з однаковими **серверними** фільтрами (розділ, профіль розмірів, стан, ціна, матеріал) об'єднуються в один запит (до 50 брендів). Категорії групу не дроблять: вони фільтруються локально за `catalogSlug` товару.
2. Беремо 100 найновіших товарів кожної групи (`orderBy` за датою додавання); якщо вся сторінка нова — догортаємо до 3 сторінок.
3. Нові id (яких немає в стані) звіряються з правилами груп, що їх повернули: категорія, вік оголошення, слова-виключення, матеріал (regex по назві, опису й полю «Матеріал» з картки). Річ, яку знайшли кілька правил, приходить один раз.
4. Для кожного відповідного товару: картка товару → повідомлення в Telegram (альбом до 3 фото + підпис).
5. Стан (`state.json`: бачені id, готові бренди груп, здоров'я, статистика) зберігається в окремій гілці `state` (один коміт, перезаписується).

**Перший запуск** для нового бренду (або бренду зі зміненими серверними фільтрами) лише запам'ятовує його поточні товари, нічого не надсилає. Решта брендів тієї ж групи працює як звичайно. Зміна категорій нічого не скидає.

## Пакети: як часто опитувати

Кількість запитів залежить від кількості **груп**, а не брендів: один запит бере до 100 брендів з однаковими серверними фільтрами. Пакети дозволяють опитувати рідкісні й порожні бренди рідше.

| Пакет | Інтервал | Брендів | Що там |
|---|---|---|---|
| `гарячі` | 10 хв | 55 | ≥30 нових речей у моїх розмірах за 30 днів (Stone Island, Ralph Lauren, Lacoste…) + батьківські бренди саб-лейблів |
| `звичайні` | 10 хв | 76 | 4–29 за 30 днів; сюди ж потрапляють нові бренди з `/add` |
| `рідкісні` | 30 хв | 137 | 1–3 за 30 днів |
| `тихі` | 3 год | 176 | є в моїх розмірах, але 0 за 30 днів |
| `не мої розміри` | доба | 62 | є в чоловічому, але не в моїх розмірах |
| `сплячі` | тиждень | 80 | лише жіноче/дитяче/аксесуари або 0 товарів |
| `текст щодня` / `текст щотижня` | доба / тиждень | 196 | бренду на Shafa немає — текстовий пошук у назвах (`text` + `title_include`) |

Пакети з інтервалом 10 хв опитуються щоразу; повільніші — коли настав їхній час, але не більше `max_slow_requests_per_run` (6) запитів за прохід, найбільш прострочені першими. Типовий прохід — 4–10 запитів, ~20 с. Пакет бренду — поле `package`; інтервали — `settings.packages`.

## Фільтри шуму

- **Перекупники й репліки** (`reseller_filter`, увімкнено за замовчуванням): у назві «s-xl», «s, m, l, xl», «розміри від s до xl», «репліка», «1:1», «люкс якість», «опт», «під замовлення». «l-xl» (одна річ на межі розмірів) не відсіюється.
- **Повтори**: та сама назва з тією самою ціною за 7 днів приходить один раз (перевиставлення).
- **«Підняті» старі оголошення**: `max_age_hours: 72`.
- **Мірки з опису** (`measurements`): пояс (напівобхват ≥45 см; повний обхват ділиться на 2), довжина штанів ≥110 см, по внутрішньому шву ≥80 см (і «W34 L30» у дюймах), устілка 28.5–30 см. Немає мірок — річ проходить; мірки суперечать одна одній — теж проходить.
- **Саб-лейбли** (RRL, Purple Label, NB Made in USA, LVC…) — пошук усередині батьківського бренду з `title_include` (фраза в назві, без запиту картки).

## Як додати бренд

1. Додай блок у `brands.yaml` (можна без id):
   ```yaml
   - name: Massimo Dutti
     categories: [сорочки, светри]
     max_price: 2000
   ```
2. Підстав id:
   ```bash
   python tools/lookup.py fill
   ```
   Однозначний збіг назви вписується у файл сам; неоднозначні друкуються списком — вибери вручну (`python tools/lookup.py brand "massimo"` або число з `brands=` в адресі сайту).
3. Закоміть зміну (можна прямо у веб-інтерфейсі GitHub). Наступний запуск запам'ятає поточні товари бренду, далі прийдуть лише нові.

Вимкнути бренд: `enabled: false`.

### Профіль розмірів

Задається один раз у `my_sizes` і діє для всіх брендів. Групи розмірів мають різні id, тож «L», «W32» і «43» не плутаються; сервер об'єднує їх через АБО.

```yaml
my_sizes:
  одяг: [L, XL]          # XS S M L XL XXL 3XL … або 46/48/50
  штани: [W32, W33]      # W28 … W50
  взуття: [43]           # 36 … 50, половинки: 42.5
```

### Категорії

Людські назви → slug-и Shafa (повний список: `python tools/lookup.py categories`): джинси, штани, брюки, шорти, футболки, поло, сорочки, светри, кардигани, худі, світшоти, лонгсліви, гольфи, кофти, верхній одяг, куртки, пуховики, пальто, парки, жилетки, піджаки, костюми, взуття, кросівки, кеди, черевики, туфлі, мокасини, спорт… Можна й сирий slug (`obuv/uggi`, або `obuv` = усе взуття). Без `categories` — усе в моїх розмірах.

### Винятки для бренду: `searches`

```yaml
- name: Visvim
  id: 64003
  searches:
    - name: взуття
      categories: [взуття]
      sizes: {взуття: [42.5, 43]}   # замінює лише групу «взуття» профілю
    - categories: [джинси, сорочки]
```

### Пошуки без бренду

```yaml
searches:
  - name: Вовняні светри
    categories: [светри]
    materials: [вовна, кашемір]
    materials_include: "(?<!ба)вовн|шерст|кашемір|merino|wool|cashmere"
    max_price: 2000
```

Запит звужується до спільного розділу категорій (`kofti`, `obuv`…), решта — локально. Пошук без категорій, матеріалу й ціни заборонено (це весь сайт). Обсяг: чоловічі светри L–XL, стан 1–3 — сотні на добу; з матеріалом — десятки.

### Матеріали за категоріями

Для всіх брендів і пошуків одразу. Матеріал шукається в назві, описі й полі «Матеріал» (українською, російською, англійською). «Штучна шкіра», «екошкіра», «PU leather» шкірою не вважаються; «бавовна» не рахується вовною.

```yaml
category_materials:
  светри: {only: [вовна, кашемір, альпака, ангора]}   # лише такі; без вказаного матеріалу — відсіяти
  взуття: {prefer: [шкіра, замша, нубук]}             # ⭐ і звук для збігу, решта приходить тихо
```

`if_unknown: send` у правилі `only` — надсилати й речі без вказаного матеріалу. Матеріали: вовна, кашемір, альпака, ангора, мохер, верблюжа вовна, шовк, льон, бавовна, шкіра, замша, нубук, акрил, поліестер. Перевірка на живих даних (9.11.2026): зі 17 светрів L/XL пройшли 6 (вовна/кашемір), 7 відсіяно (бавовна/акрил), 4 — матеріал не вказано.

### Поля правила

| Поле | Що робить | Де фільтрується |
|---|---|---|
| `section` | `men` (словники розмірів і категорій є лише для нього), `women`, `kids`, `null` | сервер |
| `sizes` | словник як у `my_sizes` (замінює вказані групи) або список сирих id (`python tools/lookup.py sizes men`) | сервер |
| `categories` | список назв або slug-ів | локально |
| `min_condition` | 1 Новий, 2 Ідеальний, 3 Дуже хороший, 4 Хороший, 5 Задовільний; `3` = «3 і краще» | сервер |
| `max_price` / `min_price` | грн | сервер |
| `materials` | до 3 id матеріалу (поле продавця). **Id різні в різних категоріях**: назви (вовна, кашемір, льон…) — це id для кофт і светрів; для сорочок льон 1712, шовк 1725; для штанів льон 1967, шовк 1979 (`python tools/lookup.py materials rubashki`) | сервер |
| `materials_include` / `materials_exclude` | regex по назві + опису + полю «Матеріал». Увага: «бавовна» містить «вовн», пиши `(?<!ба)вовн` | локально |
| `keywords_exclude` | regex по назві, напр. `"дитяч\|підліт"` | локально |
| `max_age_hours` | ігнорувати «підняті» старі оголошення (за замовчуванням 72) | локально |
| `package` | пакет частоти (`settings.packages`) | — |
| `title_include` | regex, який має бути в назві (саб-лейбли, текстові пошуки) | локально, без картки |
| `text` | серверний текстовий пошук у назвах | сервер |
| `reseller_filter` | `false` — не відсіювати перекупників для цього правила | локально |

## Керування з Telegram

Бренди, стан і розміри можна міняти командами боту, без редагування файлів. Команди виконуються на наступному проході воркфлоу (до ~10 хв): бот читає повідомлення (`getUpdates`), змінює `brands.yaml` (коментарі зберігаються), перевіряє, що конфіг валідний, комітить його в `main` і відповідає в чат. Приймаються лише повідомлення з `TG_CHAT`.

| Команда | Що робить |
|---|---|
| `/status` | розміри, стан, кількість брендів |
| `/brands` · `/brands cos` | список брендів · пошук |
| `/add Our Legacy` · `/add Our Legacy: сорочки, светри` | додати бренд (id шукається на Shafa; якщо збіг неточний — кнопки з варіантами) |
| `/remove COS` | прибрати бренд |
| `/off COS` · `/on COS` | призупинити / увімкнути |
| `/condition` · `/condition 2` · `/condition COS 1` · `/condition COS default` | мінімальний стан: кнопки · для всіх · для бренду · як у всіх |
| `/sizes` · `/sizes одяг L XL` · `/sizes штани W34 W36` · `/sizes взуття 45 45.5 46` · `/sizes взуття -` | розміри для всіх брендів |
| `/materials` · `/materials светри: вовна, кашемір` · `/materials светри + альпака` · `/materials светри - кашемір` · `/materials светри невідомі так` · `/materials светри off` | матеріали категорії: лише такі (без вказаного матеріалу — відсіяти, якщо не «невідомі так») |
| `/prefer взуття: шкіра, замша` · `/prefer взуття + нубук` · `/prefer взуття off` | пріоритет: збіг приходить зі ⭐ і звуком, решта — без звуку |

Зміна розмірів або стану змінює серверні фільтри, тож перший прохід після неї лише запам'ятовує поточні речі (без спаму). Без вебхука й окремого сервера — усе в тому самому безкоштовному воркфлоу; миттєві відповіді потребували б вебхука (наприклад, Cloudflare Workers Free).

## Налаштування з нуля

1. **Telegram-бот:** у Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` → збережи токен. Напиши своєму боту будь-яке повідомлення. Відкрий `https://api.telegram.org/bot<TOKEN>/getUpdates` і візьми `chat.id`.
2. **Секрети:** репозиторій → Settings → Secrets and variables → Actions → New repository secret: `TG_TOKEN` і `TG_CHAT`. Або з термінала:
   ```bash
   gh secret set TG_TOKEN
   ```
   ```bash
   gh secret set TG_CHAT
   ```
   Без секретів воркфлоу працює в режимі dry-run (лише лог).
3. **Перевірка вигляду:** Actions → shafa-watch → Run workflow → `demo: 2`. Прийдуть 2 найсвіжіші відповідні товари, стан не зміниться.

## Локальний запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```
```bash
TG_TOKEN=... TG_CHAT=... .venv/bin/python -m shafa_watch
```

Прапорці: `--dry-run` (не слати в Telegram), `--demo N` (надіслати N товарів по черзі з різних правил, ігноруючи стан), `--config`, `--state`, `-v`.

Тести логіки (офлайн, без мережі):
```bash
.venv/bin/python -m unittest discover -s tests -v
```

## Моніторинг

- ⚠️ алерт у Telegram, якщо: Shafa повертає 403/429 (можливе блокування IP), запит групи падає 3 рази поспіль, група, що раніше мала товари, повертає 0 товарів 12 запусків поспіль, усі запити впали, не вдалося надіслати повідомлення. Повтор того самого алерту не частіше ніж раз на 6 год; після відновлення приходить ✅.
- 💓 щоденний heartbeat після 9:00 за Києвом: кількість запусків, сповіщень, запитів, помилок, найбільша пауза між запусками.
- **Якщо heartbeat не прийшов** — воркфлоу не запускався: тригери (Apps Script → Executions, Cloudflare → Logs, листи Google), сплив токен, вичерпана квота або збій GitHub. Перевір вкладку Actions.

## Самозапуск: три шари

Розклад GitHub (`schedule`) для цього репо не спрацював за 40+ хв після ввімкнення, а в пік запізнюється на 5–30 хв. Тому воркфлоу запускають три незалежні шари; жоден не потребує мого комп'ютера чи ручних дій.

| Шар | Де працює | Як часто | Токен |
|---|---|---|---|
| 1. [tools/trigger.gs](tools/trigger.gs) + сторож | Google Apps Script (мій Google-акаунт) | кожні 10 хв | fine-grained №1 |
| 2. [tools/cloudflare-worker.js](tools/cloudflare-worker.js) | Cloudflare Workers Free | кожні 10 хв (`5-59/10`) | fine-grained №2 |
| 3. `schedule` у `watch.yml` | GitHub | раз на 2 год (`41 */2`) | вбудований `GITHUB_TOKEN`, не спливає |

- **Замок (шари 1–2):** перед запуском тригер дивиться останній запуск воркфлоу (без урахування `schedule`). Якщо він був < 9 хв тому або ще йде — пропуск. Тож при двох живих тригерах запусків усе одно ~1 на 10 хв.
- **Шар 3:** задача `gate` перевіряє, чи були інші запуски за 15 хв. Були — основна задача `watch` не стартує (витрачається лише ~1 хв `gate`). Не було — запускає перевірку й пише warning в Actions. Якщо `gate` сам упав — перевірка все одно йде.
- **Сторож (шар 1):** успішного запуску від тригерів не було 30+ хв → ⚠️ у Telegram (повтор раз на 3 год), після відновлення ✅. За 14 днів до закінчення токена №1 — 🔑 нагадування щодня.
- Збій функції Apps Script → лист від Google; збій Worker → Cloudflare → Observability → Logs.
- Токени: fine-grained, лише репозиторій `PhPaster/shafa-watcher`, **Actions: Read and write**. 404 = репозиторій не вибрано в токені, 401 = токен недійсний або сплив. Окремий токен на кожен шар, щоб збій одного не вимикав обидва.
- Діагностика Apps Script: функція `check` (доступ токена, дата закінчення, останні запуски, тест Telegram). Функції: `setup`, `dispatch`, `check`, `stop`.

Що коли ламається:

| Збій | Що далі |
|---|---|
| Google / Apps Script | Cloudflare запускає кожні 10 хв; сторожа немає → видно лише в heartbeat |
| Cloudflare | Apps Script запускає кожні 10 хв |
| Обидва (або спливли обидва токени) | GitHub раз на 2 год (якщо його розклад працює); ⚠️ від сторожа, якщо живий Apps Script |
| GitHub Actions / квота | нічого не запускається; ⚠️ від сторожа |

## Ліміти й вартість

Приватний репозиторій на GitHub Free має $12 безкоштовного використання Actions на місяць. Раннер `ubuntu-slim` коштує $0.002/хв, запуск кожні 10 хв ≈ 4 464 запуски × 1 хв ≈ $8.9/міс, плюс резервний розклад GitHub раз на 2 год ≈ 372 × 1 хв задачі `gate` ≈ $0.7 → **≈ $9.7/міс (~81 %), вкладається, нічого не платиш**. Частіший резервний розклад або тригери без замка квоту перевищать. Без прив'язаної картки після вичерпання квоти запуски просто зупиняються, грошей не списують.

- Кожні 5 хв у приватному репо ≈ $17.9/міс → **не вкладається**.
- Публічний репо: безкоштовно без ліміту, можна кожні 5 хв (`cron: "*/5 * * * *"`), але `brands.yaml` і стан видно всім, а після 60 днів без комітів GitHub вимикає розклад.

Деталі розрахунків: [FINDINGS.md](FINDINGS.md#ліміти-безкоштовних-хостингів-перевірено-9112026-в-офіційній-документації).

## Якщо Shafa блокує

Не обходимо блокування (жодних проксі чи капч). Варіанти по черзі:
1. Зменшити частоту (`cron`) і збільшити `request_delay_sec`.
2. Запускати з домашнього комп'ютера (домашній IP блокують рідше): macOS `launchd` або `cron`:
   ```bash
   crontab -e
   ```
